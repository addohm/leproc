# CLAUDE.md

Orientation for Claude working on leproc. Read this first.

## What this is

Leproc is a WoW: Forever addon (Interface 16001: the modern retail client with the
Midnight "secret values" addon API, running Classic level-60 content), for every
class. It glows an ability's action button when the ability is ready, **whatever
stance or form the player is in**. That's the gap it closes: ProcGlow (and the
game) only light Revenge in Defensive Stance, because they ask the game whether
the button is usable, and the game says no in the wrong stance.

How (0.x; step 2 of the rebuild brings it back under ProcGlow's per-button
rule): in an ability's own stance the game's `C_Spell.IsSpellUsable` decides (exact
at both ends). Elsewhere the game says no, so Leproc uses the blocks, dodges and
parries the game reports to addons even in combat (`UNIT_COMBAT`: only the
amount is secret): 0.x's `Track.lua` opened a window of 5 s minus the
measured report delay (the reports arrive 0.2-0.9 s after the game's own
change), closed it when the player cast the ability, and kept it dark for the
ability's cooldown; `Bars.lua` drew the glow on Leproc's own overlay frames on
the action buttons of any bar addon (the owner uses EllesmereUI's). Both are in
git history (tag `v0.9.0-beta`). The options window, profiles, glow styles and
minimap button are Leboof's (the owner's other addon, `addohm/leboof`),
adapted.

**Being rebuilt since 2026-11-18** (ROADMAP.md, "The rebuild"): Leproc starts
over with ProcGlow as its base, all of its features rebuilt in our own code and
look, keeping the any-stance glow. Step 1 (the window, profiles, minimap,
Options > AddOns) is in; nothing glows until step 2. The conventions below
keep 0.x's lessons for the steps to come.

`ProcGlow/` (by Troy) is the base for the rebuild: rebuild what it does, never
copy its code. It's git-ignored; never commit it.
The remote is `addohm/leproc` on GitHub (`origin`, branch `main`).

## Layout

- `README.md`: what it is, setup and usage
- `CHANGELOG.md`: changes, newest first, under *Unreleased* until a release
- `DEPLOY.md`: how it's deployed and run live
- `SECURITY.md`: secrets, access, reporting problems
- `ROADMAP.md`: done, next, ideas
- `CLAUDE.md`: this file
- `TESTING.md`: what to check in game, and what's been confirmed
- `Leproc/`: the addon (what players copy into `Interface\AddOns`).
  `Leproc.toc` sets the load order and holds `## Version`, the only version
  source.
  - `Build.lua`: build stamp, empty in the repo; the install script writes the
    commit into it.
  - `Data.lua`: GENERATED by `tools/gen_data.py`. Never edit by hand. 0.x's
    spell IDs, used again from step 2.
  - `Abilities.lua`: 0.x's catalogue (each ability's key, names, class,
    triggers, stance, cooldown, note; `ns.WINDOW`), unused until step 2
    reworks it; `tools/gen_data.py` reads its names.
  - `Core.lua`: the defaults (`ns.DEFAULTS`: enabled, loginMessage,
    classColour, window, minimap), `ns.Version(withBuild)` (the build only
    in chat, never in the window: the owner's rule), `ns.Secret(v)`, `ns.Enabled()` and
    `ns.SetEnabled()`, `ns.Refresh()` (the theme, minimap button and window
    follow `ns.db`), `ns.ResetAll()` (asks, then `LeprocDB = nil` and
    `ReloadUI`), the login message (`LeprocDB.welcomed`: a welcome the first
    time), `/leproc`.
  - `Profiles.lua`: profiles, as Leboof's. `LeprocDB.profiles[name]` holds every
    setting; `LeprocDB.chars["First Last"]` is the profile each character uses;
    `ns.db` is the one in use. Switching by talents or role (ProcGlow's idea):
    `LeprocDB.auto["First Last"]` = `{ on, spec = { [tree] = profile },
    role = { TANK/HEALER/DAMAGER = profile } }`. `P.Spec()` reads Forever's
    talents: `C_ClassTalents.GetActiveConfigID` -> `C_Traits.GetConfigInfo`
    (`treeIDs[1]`) -> `C_Traits.GetGroupDisplayInfoByTreeID` (a group per
    talent tree, by `orderIndex`) -> `C_Traits.GetGroupCurrencyInfo` (points
    `spent`); the classic `GetTalentTabInfo` and the class's tree names as
    fallbacks. `P.Role()` (`UnitGroupRolesAssigned`, only in a group).
    `P.Auto(force)`: a role rule first, then the tree with the most points;
    acts when they change, waits for `PLAYER_REGEN_ENABLED`. Rename and
    Delete keep the rules in step (`P.EachRule`).
  - `Glow.lua`: Leboof's glow styles (`Glow.Build`, `Glow.Show`), unused until
    step 3.
  - `UI/Theme.lua`: the window's colours: `Theme.Accent()` and `Theme.Edge()`
    (gold, or the class colour with `classColour`), `Theme.Paint(fn)` (run
    now and on every `Theme.Apply()`).
  - `UI/Widgets.lua`: option rows (check, arrow picker, edit box, button,
    heading with a themed rule, text) and the scrolling `UI.Stack`, in
    Leboof's and Nothing Wasted's style.
  - `UI/Window.lua`: the options window: tabs (`Window.AddPage`, or
    `Window.Page` for a page of rows; `order` sets the place), Defaults
    (`Window.RunDefaults`), the resize grip, `Window.Apply()` when the
    profile changes, and
    `Window.Register()` (Options > AddOns, with an Enable box).
  - `UI/Minimap.lua`: the minimap button (either click opens the window; grey
    while Leproc is off; square minimaps), and the addon compartment entry.
    Profiles are managed on their tab only (the owner, 2026-11-18).
  - `UI/Pages/General.lua`, `UI/Pages/Profiles.lua`: those tabs.
    `UI/Pages/Soon.lua`: the tabs not built yet (Procs & Buffs, Glow, Timer &
    Stacks, Text Alerts); each moves to its own file with its step.
  - `Media/Icon.tga`: the in-game icon, drawn by `art/make_logo.py`. Never edit
    by hand.
- `art/`: `make_logo.py` (Pillow) and what it draws: the icon PNGs (512, 400
  for the listing avatar, 256, 128) and `leproc-banner.png` (1600x500; needs
  Inter in `.scratch/fonts/`, see DEPLOY.md).
- `LISTING.md`: the CurseForge / Wago pitch page (basics, summary,
  description, screenshot list, release notes). Keep its feature list in step
  with README.md.
- `release/`: `Leproc-<version>.zip` packages for players, built by
  `tools/make_release.py`; committed with each release (tagged
  `v<version>`).
- `tools/gen_data.py`: fetches Forever's SpellName table from wago.tools and
  writes `Data.lua` (every ID for each ability and stance name).
- `tools/compare_logs.py <leproc log> <WoWCombatLog.txt> [--player Kam]`: the
  ground truth from the game's combat log (whose attack was dodged, blocks,
  parries, casts) against Leproc's log (copied text or `Leproc.lua`): when
  Overpower and Revenge should have been lit, false glows and misses with
  the stance and the trigger, and for every "your target dodged" whose attack
  it was and whether the probes came with it. Tested on
  `tests/fixtures/` (made-up logs in the real formats) by `run_tests.py`.
  Check its parsing against the first real combat log (the damage suffix's
  "blocked" position, the 17 advanced params).
- `tools/forever_tooltips.py <names>`: Wowhead's Forever tooltip for every ID
  with each name, to check a spell or proc buff before adding it.
- `tools/install_forever.cmd`: Windows; pulls, mirrors `Leproc/` into the
  client, stamps `Build.lua`, packs a zip on the desktop (CRLF, see
  `.gitattributes`)
- `tools/make_release.py`: builds `release/Leproc-<version>.zip` from the
  committed `Leproc/` folder
- `tests/`: `wowmock.lua` (a fake client: Forever's talent trees (`WM.trees`),
  groups and roles (`WM.group`, `WM.role`), class colours, and from
  0.x, for step 2: action buttons with stance pages,
  bar addons' buttons (`WM.AddonBar`, `WM.Button`), macros with text
  (`WM.SetMacro`), aura containers (`WM.SetAura`, `WM.ProcGlowing`), the
  game's reactive state (`WM.Combat(unit, event, flags, lag)` sets it at once
  and reports `lag` s later, like the real game; `WM.GameUsable`, `WM.short`),
  `EnumerateFrames`,
  combat events, a clock), `smoke.lua` (scenarios), `run_tests.py` (also checks
  the globals named frames make while the scenarios run, and runs
  `tools/compare_logs.py` on `tests/fixtures/`).
- `ProcGlow/`: someone else's addon, a design example only (git-ignored, local)
- `.scratch/`: git-ignored downloads (Blizzard UI source, the wago.tools CSV),
  and `procglow-inventory.md`: everything ProcGlow does, area by area, with its
  defaults and edge cases (2026-11-18; local to this workspace).

## Workflow

1. Start from the latest: pull before changing anything.
2. Make the change with tests.
3. **Update the docs in the same commit.** Every change updates the docs it
   affects:
   - README.md: setup and usage
   - CHANGELOG.md: an entry under *Unreleased*
   - DEPLOY.md: when deploying or running it live changes
   - SECURITY.md: when secrets, access or permissions change
   - ROADMAP.md: when something on it is done, or new plans are made
   - TESTING.md: what needs checking in game, and results the owner reports
   - LISTING.md: when a feature players see changes
   - this file: when the layout, workflow or conventions change
4. Run the checks: `.venv/bin/python tests/run_tests.py` (set up with
   `python3 -m venv .venv && .venv/bin/pip install lupa`). Then commit and push,
   and say "Pushed: <commit>" so the owner can run the install script.
5. **A release ships its whole kit** (the owner, 2026-11-08, for this and every
   future package): the version bump, the zip from `tools/make_release.py`, the
   tag, LISTING.md up to date, and the art. Steps in DEPLOY.md.

## Conventions

- **Debug glows against the combat log, not guesses.** Ask the owner for
  `/leproc log` and `/combatlog` from the same session (TESTING.md), run
  `tools/compare_logs.py`, and fix by the kind of mismatch it reports.
- **Ask the game only where it can answer.** In an ability's own stance (or
  always, for abilities without one) `C_Spell.IsSpellUsable` is the truth:
  exact, and "short of power" still counts as lit. Outside the stance it says
  no regardless (the gap Leproc closes), so it's never asked there: the
  trigger window decides, shortened by the measured report delay. The
  cooldown comes from the player's own cast (the game's "usable" ignores
  cooldowns), the stance from `GetShapeshiftFormInfo`. The owner's logs
  (TESTING.md) are the evidence: keep reading new ones before changing this.
  A target's dodge only counts while the player is in combat
  (`UnitAffectingCombat`): the game doesn't say whose attack it was.
- **Check what's secret** in Blizzard's API docs, `forever` branch
  (`Blizzard_APIDocumentationGenerated`):
  https://github.com/Gethe/wow-ui-source/tree/forever. Skip secret values with
  `issecretvalue`, never compare them. `UNIT_COMBAT`'s event and flagText aren't
  secret; health (`UnitHealth`) is, so Execute can't be done this way.
- **Never read buffs for a glow.** Proc buffs go through `Procs.lua`: the game
  shows the glow with the buff. Don't touch a slot's button or its children in
  combat (closed to addons while auras are secret); place them out of combat.
  Proc buff IDs are explicit (`buffIds`), checked on Wowhead's Forever
  tooltips (`tools/forever_tooltips.py <names>` prints them): keep only the
  "Instant" auras, never a "Talent" or a rune's "Gain the ... ability" (a
  talent's ID could match a passive aura all the time). Forever-new spells
  have IDs around 1,2xx,xxx-1,3xx,xxx; Season of Discovery's around 400,000.
  The wiki rate-limits scripted reads.
- **A partial block is a `WOUND` flagged `BLOCK_REDUCED`** (most Classic blocks
  are partial); a full block is `BLOCK`, or a `WOUND` flagged `BLOCK`
  (CombatFeedback.lua).
- **Find buttons by what they hold, not by name**, so any bar addon works:
  any button with an action slot counts, and hidden ones (Blizzard's under
  EllesmereUI) never glow because they aren't visible. The tests check every
  bar on ProcGlow's list by name; names are only used to notice late bars
  (`Bars.LATE`).
- **ProcGlow is the reference for what the addon must handle** (bars, macros,
  abilities, edge cases): check how it handles something before building the
  same thing, and take the idea, never the code.
- **Glows go on Leproc's own overlay frames**, never on the buttons themselves:
  don't set fields or scripts on the buttons, and don't call protected functions.
  Display only: never automate anything.
- **Check an ability against Forever before adding it** (Wowhead's Forever
  tooltips, `nether.wowhead.com/forever/tooltip/spell/<id>`, and the wiki's
  `<Class>_abilities_(Forever)` pages). Forever's spell data also holds spells
  that aren't in the game. Mongoose Bite follows the hunter's own dodge, not the
  target's (ProcGlow has it the other way round).
- Ability and stance spell IDs come from `Data.lua`, by name (proc buffs
  excepted, above). Add an ability to `Abilities.lua` and
  run `tools/gen_data.py`; it reports names with no IDs.
- **Keep it simple:** a button glows or it doesn't. Nothing else animates.
- Lua 5.1, no libraries (Ace, LibStub). Every file starts `local _, ns = ...`;
  shared state goes on `ns`. Globals: `LeprocDB`, `LeprocFrame`,
  `LeprocMinimapButton`, `SLASH_LEPROC1/2`, `Leproc_OnAddonCompartmentClick`
  (the tests enforce this; `LeprocLog` comes back with the log in step 2).
- **Use the game's own pieces where Blizzard offers them**: its menus
  (`MenuUtil`) for dropdowns and context menus, `Settings` for Options >
  AddOns, `StaticPopupDialogs` to confirm. Check the `forever` branch's API
  docs before relying on a function (Forever's talents are trait trees, not
  the classic talent tabs).
- No code copied from other addons (ProcGlow included). Code shared with
  Leboof is the owner's own.

## Don't

- Commit secrets (`.env`, keys, tokens), `.venv/`, `.scratch/` or `ProcGlow/`.
