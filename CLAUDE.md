# CLAUDE.md

Orientation for Claude working on leproc. Read this first.

## What this is

Leproc is a WoW: Forever addon (Interface 16001: the modern retail client with the
Midnight "secret values" addon API, running Classic level-60 content), for every
class. It glows an ability's action button when the ability is ready, **whatever
stance or form the player is in**. That's the gap it closes: ProcGlow (and the
game) only light Revenge in Defensive Stance, because they ask the game whether
the button is usable, and the game says no in the wrong stance.

How: the game reports blocks, dodges and parries to addons even in combat
(`UNIT_COMBAT`: only the amount is secret). `Track.lua` opens a 5 s window on the
trigger, closes it when the player casts the ability, and keeps it dark for the
ability's cooldown. `Bars.lua` draws the glow on Leproc's own overlay frames on
Blizzard's action buttons. The options window, profiles, glow styles and minimap
button are Leboof's (the owner's other addon, `addohm/leboof`), adapted.

Scope agreed on 2026-11-08: for every class, glowing the action buttons (not
icons of its own), "Any stance" by default with "Only in its stance" as an
option. The first chunk is the block/dodge/parry abilities; next are buff procs,
a health probe for Execute, and other bar addons (ROADMAP.md).

`ProcGlow/` (by Troy) is the owner's design example: read it for ideas, don't
copy its code. It's git-ignored; never commit it.
The remote is `addohm/leproc` on GitHub (`origin`, branch `main`).

## Layout

- `README.md`: what it is, setup and usage
- `CHANGELOG.md`: changes, newest first, under *Unreleased* until a release
- `DEPLOY.md`: how it's deployed and run live
- `SECURITY.md`: secrets, access, reporting problems
- `ROADMAP.md`: done, next, ideas
- `CLAUDE.md`: this file
- `TESTING.md`: what to check in game, and what's been confirmed
- `Leproc/`: the addon (what players copy into `Interface\AddOns`).
  `Leproc.toc` sets the load order and holds `## Version`, the only version
  source.
  - `Build.lua`: build stamp, empty in the repo; the install script writes the
    commit into it.
  - `Data.lua`: GENERATED by `tools/gen_data.py`. Never edit by hand.
  - `Abilities.lua`: the catalogue: each ability's key, names, class, triggers
    (`after`), required stance, cooldown, note; `ns.WINDOW` (5 s).
  - `Core.lua`: the defaults (`ns.DEFAULTS`), modes (`any`, `stance`, `off`),
    sounds (`ns.SOUNDS`, `ns.Play`), events, `/leproc`. `ns.byKey`,
    `ns.bySpell` (every rank's ID -> entry), `ns.ClassEntries()`.
  - `Profiles.lua`: profiles, as Leboof's. `LeprocDB.profiles[name]` holds every
    setting; `LeprocDB.chars["First Last"]` is the profile each character uses;
    `ns.db` is the one in use.
  - `Glow.lua`: Leboof's glow styles (`Glow.Build`, `Glow.Show`).
  - `Track.lua`: the trigger windows (`UNIT_COMBAT`), casts and cooldowns
    (`UNIT_SPELLCAST_SUCCEEDED`), the stance check (`GetShapeshiftFormInfo`),
    `Track.IsLit(e)`, `Track.Update()` (also plays the sound), `Track.Test()`.
  - `Bars.lua`: the overlays on Blizzard's action buttons (made at login), what
    each button holds (`GetActionInfo(button.action)`: a spell, or a macro that
    casts one), `Bars.Update()`, `Bars.OnScreen(e)`.
  - `UI/Widgets.lua`, `UI/Window.lua`, `UI/Minimap.lua`: Leboof's, adapted.
    `UI/Pages.lua`: the Abilities, Glow, General and Profiles tabs.
  - `Media/Icon.tga`: the in-game icon, drawn by `art/make_logo.py`. Never edit
    by hand.
- `art/`: `make_logo.py` (Pillow) and the icon PNGs it draws (512, 400 for a
  listing avatar, 256, 128).
- `tools/gen_data.py`: fetches Forever's SpellName table from wago.tools and
  writes `Data.lua` (every ID for each ability and stance name).
- `tools/install_forever.cmd`: Windows; pulls, mirrors `Leproc/` into the
  client, stamps `Build.lua`, packs a zip on the desktop (CRLF, see
  `.gitattributes`)
- `tools/make_release.py`: builds `release/Leproc-<version>.zip` from the
  committed `Leproc/` folder
- `tests/`: `wowmock.lua` (a fake client: action buttons with stance pages,
  combat events, a clock), `smoke.lua` (scenarios), `run_tests.py`.
- `ProcGlow/`: someone else's addon, a design example only (git-ignored, local)
- `.scratch/`: git-ignored downloads (Blizzard UI source, the wago.tools CSV).

## Workflow

1. Start from the latest: pull before changing anything.
2. Make the change with tests.
3. **Update the docs in the same commit.** Every change updates the docs it
   affects:
   - README.md: setup and usage
   - CHANGELOG.md: an entry under *Unreleased*
   - DEPLOY.md: when deploying or running it live changes
   - SECURITY.md: when secrets, access or permissions change
   - ROADMAP.md: when something on it is done, or new plans are made
   - TESTING.md: what needs checking in game, and results the owner reports
   - this file: when the layout, workflow or conventions change
4. Run the checks: `.venv/bin/python tests/run_tests.py` (set up with
   `python3 -m venv .venv && .venv/bin/pip install lupa`). Then commit and push,
   and say "Pushed: <commit>" so the owner can run the install script.

## Conventions

- **Never ask the game whether an ability is usable** (`IsUsableAction`,
  `C_Spell.IsSpellUsable`): outside the right stance it says no, which is the
  gap Leproc closes. Lit comes from the trigger window, the cooldown from the
  player's own cast, and the stance (mode `stance` only) from
  `GetShapeshiftFormInfo`.
- **Check what's secret** in Blizzard's API docs, `forever` branch
  (`Blizzard_APIDocumentationGenerated`):
  https://github.com/Gethe/wow-ui-source/tree/forever. Skip secret values with
  `issecretvalue`, never compare them. `UNIT_COMBAT`'s event and flagText aren't
  secret; health (`UnitHealth`) is, so Execute can't be done this way.
- **A partial block is a `WOUND` flagged `BLOCK_REDUCED`** (most Classic blocks
  are partial); a full block is `BLOCK`, or a `WOUND` flagged `BLOCK`
  (CombatFeedback.lua).
- **Glows go on Leproc's own overlay frames**, never on Blizzard's buttons:
  don't set fields or scripts on the buttons, and don't call protected functions.
  Display only: never automate anything.
- **Check an ability against Forever before adding it** (Wowhead's Forever
  tooltips, `nether.wowhead.com/forever/tooltip/spell/<id>`, and the wiki's
  `<Class>_abilities_(Forever)` pages). Forever's spell data also holds spells
  that aren't in the game. Mongoose Bite follows the hunter's own dodge, not the
  target's (ProcGlow has it the other way round).
- Spell IDs come from `Data.lua`, by name. Add an ability to `Abilities.lua` and
  run `tools/gen_data.py`; it reports names with no IDs.
- **Keep it simple:** a button glows or it doesn't. Nothing else animates.
- Lua 5.1, no libraries (Ace, LibStub). Every file starts `local _, ns = ...`;
  shared state goes on `ns`. Globals: `LeprocDB`, `LeprocFrame`,
  `LeprocMinimapButton`, `SLASH_LEPROC1/2`, `Leproc_OnAddonCompartmentClick`
  (the tests enforce this).
- No code copied from other addons (ProcGlow included). Code shared with
  Leboof is the owner's own.

## Don't

- Commit secrets (`.env`, keys, tokens), `.venv/`, `.scratch/` or `ProcGlow/`.
